EmulatRx · MCP 功能接口与 Agent 编排逻辑设计蓝图

核心设计理念：不当“一把梭黑盒执行器”，而做 Agent 的“分步因果推断状态机”。把目标试验模拟拆成「建入口 → 对标 RCT 五维验真 → 起草与核验七要素/CCW 协议 → 秒级平衡与正值性预检 → 竞争风险/CCW 估计与结构化证据读取」五道原子工序；遇到人群/双臂/终点偏离或正值性崩溃时强制停机返回结构化原因，由 Agent 与研究者确认后再推进。后续重构可视化 Web Wizard 时可直接复用同一套分步接口。

Gate A：五维 PICO-T 偏离显式确认（防错配 RCT）；Gate B：加权均衡与正值性预检（未过门禁绝不输出有偏估计）

二、 14 项暴露给 Agent 的 MCP Tools 明细（点击阶段筛选）

Stage 1 · 起点建立、队列画像与会话隔离层（Session & Discovery） 解决“Agent 如何接手用户的自然语言想法或本地脱敏表，并在分析完物理销毁”
1. parse_research_idea 新增独立暴露

将用户的中文/英文临床研究想法解析为结构化 PICO 与标准检索词，不虚构未声明的对照药，严格区分肿瘤 EGFR 与肾病 CKD。

输入：idea_text, 可选覆写 condition / intervention / comparator / outcome
输出：pico 字典、comparator_explicit: bool、英文检索词 ctgov_queries
2. ingest_cohort_session 升级自 profile_cohort_session · 核心自有数据入口

接入用户自己的脱敏队列数据表（CSV/TSV/Excel导出表，兼容 UTF-8 与国内医院常见 GB18030 编码）：本地 stdio 模式直接传本地 file_path 零 Token 过手直读；远程 HTTP 模式签发一次性旁路上传地址 upload_url 流式直传服务器（绕开大模型上下文窗口与隐私泄露），仅将表头、缺失率、分布统计与候选字段角色返回给 Agent。（注：sample_id 仅保留作无数据时的教学演示快捷方式。）

输入：本地 file_path | 远程已传 session_id（或请求签发 issue_upload_ticket=true）| 演示用 sample_id
输出：session_id、脱敏统计画像 profile、候选角色映射 default_mapping、待向用户追问的语义缺口 missing_clinical_semantics（如表中只写了 0/1 未写药名时提示 Agent 追问）
3. delete_cohort_session 已有 · 保持强化

一键物理擦除指定会话的原始表格、元数据及全部关联派生运行目录，执行磁盘零残留校验。

输入：session_id
输出：deleted: true、purged_run_ids[]（后续读取一律返回 SESSION_NOT_FOUND）
Stage 2 · 目标试验检索与五维 PICO-T 对标层（Target RCT Alignment） 解决“不只看药名撞词，而是对设计、人群、双臂方案（含双模拟安慰剂剥离）、硬终点、随访窗五维把关”
4. search_target_rcts 已有 · 已升级五维审计

实时检索 ClinicalTrials.gov API v2（头对头双臂优先，断网明示回落离线目录），剥离 <drug> placebo 双模拟安慰剂，按五维对齐等级排序并用确定性硬上限锁死大模型评分。

输入：condition, intervention, comparator, outcome, target_followup_days, project_mode
输出：候选列表（含 nct_id、双臂解析明细、五维 dimension_audit、match_score、overall_alignment_status）
5. audit_target_rct_alignment 新增单试验精准验真

当研究者直接向 Agent 指定某个 NCT 号（如“帮我对标 NCT02296125”）时，按单号实时拉取官方注册结构并输出五维逐项核对单与偏离确认要求。

输入：nct_id（或 target_rct JSON）+ session_id 或 pico
输出：overall_alignment_status、逐维通过/偏离详情、requires_confirmation 及对应错误码说明
Stage 3 · 协议草拟与因果时间轴显式核验层（Protocol Drafting & Guardrails） 解决“让 Agent 先生成可读、可改的七要素 / CCW 协议草案交用户过目，再跑确定性防时间穿越检查”
6. draft_tte_protocol 核心新增 · 分步向导枢纽

根据选定的目标 RCT 与队列画像（或模拟 PICO），草拟完整的七要素目标试验协议（静态基线 / 固定地标 / 宽限期 CCW）与列名映射表。若目标 RCT 存在未确认偏离，在此步即刻触发 422 拦截。

输入：design_mode (static | landmark | grace_period_ccw), target_rct, session_id / pico, mapping_overrides, confirm_arm_mismatch, confirm_protocol_mismatch
输出：可审阅/可微调的 protocol_draft JSON、column_mapping 与关键参数清单（零点、宽限期、评估时点、门禁阈值）
查看 Agent 典型交互效果 
Agent 调用 draft_tte_protocol → 向研究者展示：
"已按 CAROLINA (NCT01243424) 草拟协议：t0=首次处方日，双臂=利格列汀 vs 格列美脲，
评估时点=180/365/730天，加权=Overlap，门禁 |SMD|≤0.10。是否调整地标窗或协变量？"
7. validate_tte_protocol 已有 · 静态/地标检查器

对七要素静态/地标协议执行确定性方法学规则审查：拦截缺失时间零点、零点后纳排条件穿越、地标后协变量污染及 E-value 指标误用。

输入：protocol JSON + 可选 session_id
输出：valid: bool、规范化协议、结构化 violations[]（定位违规字段与修正提示）
8. validate_ccw_protocol 新增 · 接入已合并 P1 CCW

校验 tte-ccw-v1 双侧宽限期克隆协议：核查宽限期 $g$ 与步长 $\Delta$ 整除性、时变协变量 X_tv 期前测量偏移（严防期后测量穿越）、分位截尾跨度与合成前缀守卫。

输入：ccw_protocol JSON
输出：valid: bool、离散人-期网格规格 (m_g, K)、无治疗-混杂反馈适用边界声明与 violations[]
Stage 4 · 分阶诊断预检与确定性因果估计层（Feasibility Gate & Estimation） 解决“先花 0.5 秒做倾向重叠与平衡门禁体检，通过后再启动竞争风险 / 个体聚类 Bootstrap 重计算”
9. diagnose_tte_feasibility 核心新增 · 秒级独立门禁预检

在不跑耗时生存 Bootstrap 的前提下，独立运行纳排瀑布筛选、重叠加权/IPTW（或宽限期 IPCW）拟合、ESS 有效样本量比、截尾前极值权重与加权前后协变量 |SMD| 体检。

输入：protocol + session_id + column_mapping（或模拟参数 sim_config）
输出：gate_status (passed | blocked)、纳排流失瀑布、Love Plot smd_table、未过门禁时的修复建议 remediation_hints
10. run_static_or_landmark_tte 整合升级自有/模拟/合成三轨

执行静态基线或固定地标竞争风险完整估计（门禁未过强制阻断并省略点估计；通过则计算加权 Aalen–Johansen CIF_1/CIF_2、Fine–Gray sHR、原因特异 csHR、RD/RR_CIF 与 E-value）。保留原 start_user_cohort_tte / start_simulated_rct_tte 兼容别名。

输入：project_mode, protocol, session_id / mapping（或 sim_config + seed）, target_rct, 确认位
输出：run_id、运行状态（快速任务直接附带完成态核心指标，长任务返回异步句柄）
11. run_grace_period_ccw 新增 · 接入已合并 P1 CCW

运行双侧宽限期治疗克隆–删失–加权（CCW）引擎：分臂独立稳定化 IPCW（支持 X_tv 期前时变混杂）、截尾前正值性熔断、克隆前患者级聚类 Bootstrap 重拟合，并同步输出「朴素事后分组不朽时间假阳性曲线」定量对照。

输入：ccw_protocol, synthetic_scenario（null_effect | protective_effect 或自定义 DGP 参数）, seed, bootstrap_replicates
输出：run_id、gate_status、各时点 ccw_rd vs naive_immortal_biased_rd vs truth_rd 对照
12. get_tte_run_status 已有 (get_tte_run)

查询异步估计或高次 Bootstrap 任务的实时阶段、门禁通过状态、耗时及已落盘产物列表。

输入：run_id
输出：status (running / completed / gate_blocked / failed)、artifacts[]、错误摘要
Stage 5 · 面向临床专家的「三阶渐进对比结果单」与审计导出层（Clinician-Facing 3-Tier Evidence Ladder） 核心输出原则：服务临床专家而非纯方法学专家——同屏对比「① 原始直接分析 → ② 常规 PSM/IPTW → ③ 完整 TTE」的终点值演变与额外受控偏倚归因

🎯 最终输出必含的核心「三阶去偏对比梯队（clinical_comparison_ladder）」

分析层级 输出的终点核心指标 这一步解决了什么 这一步还残留什么盲区
第一阶 · 原始粗分析
tier_1_unadjusted_crude		 原始两组例数/事件数、未调整终点发生率、粗风险差 Crude RD、粗 Crude HR (95% CI) 直观还原临床医生在 Excel/SPSS 直接做分组对比看到的原始表面数值 混杂两组基线病情轻重差异（适应证混杂）+ 时间起点与不朽时间偏倚
第二阶 · 常规倾向评分调整
tier_2_conventional_ps		 1:1 卡钳 PSM（含匹配对数与丢弃样本比例）及常规简单 IPTW 下的终点发生率、PSM/IPTW RD 与 HR (95% CI) 拉平已测量的基线特征差异（列出具体被拉平的基线变量及 SMD 下降幅度） 仍无法消除时间与设计偏倚：事后分组不朽时间假阳性、1:1 匹配丢弃大量样本、传统 KM 高估竞争死亡风险、期前时变混杂
第三阶 · 完整目标试验模拟
tier_3_target_trial_emulation		 对标目标 RCT 后的加权 CIF_1(t*)、TTE RD / RR_CIF、Fine–Gray sHR、原因特异 csHR 及未测混杂 E-value 自动生成临床大白话归因单（what_tte_controlled_beyond_psm）：逐条量化告诉临床专家“为什么从 PSM 到 TTE 终点值又发生了变化”——① 额外剔除了多少例违反时间零点/纳排规则的现患或穿越病例；② 额外消除了多少百分点不朽时间偏倚（宽限期双侧克隆 CCW）；③ 修正了多少例竞争死亡导致的高估（Aalen–Johansen vs 1-KM）；④ 额外控制了哪些纵向期前时变混杂因素并保留了多少临床重叠目标人群。
13. get_tte_result_summary 核心新增 · 临床三阶对比结构化结果单

一次性返回免 Base64 的结构化 JSON 临床结论包：首屏即为 clinical_comparison_ladder（粗分析 → 常规 1:1 PSM / 简单 IPTW → 完整 TTE 三阶终点数值对照表） + what_tte_controlled_beyond_psm（额外控制的混杂与设计偏倚临床白话归因清单），辅以纳排瀑布、平衡诊断、各时点置信区间与证据边界声明。

输入：run_id
输出：{clinical_comparison_ladder, what_tte_controlled_beyond_psm, horizon_estimates, hazard_ratios, diagnostics, evidence_tier}
14. export_tte_artifact 升级自 read_tte_artifact

按 UTF-8 文本、解析后 JSON 或分页块导出独立可打印 HTML 临床报告（首屏同样内置三阶去偏对比表与曲线）、Markdown 审计稿、CIF 阶梯曲线 CSV 及 SHA-256 run_manifest.json（保留原 read_tte_artifact 兼容）。

输入：run_id, artifact_name, mode (text | json | base64_chunk)
输出：产物正文/对象、sha256 校验值、分页游标（若超大）

四、 传输接入、鉴权隔离与实施边界

架构维度设计规格
双传输模式 ① 本地 stdio：python -m emulatrx_tte mcp-serve（Claude Desktop / Cursor / Orca / 本地科研 Agent 即插即用）；
② 远程 HTTP：POST /mcp（ymadmin 私网容器，独立 Bearer Token 鉴权，与 Web 口令强制不同）。
隐私与确定性红线 所有统计加权、生存曲线与门禁 100% 由纯 Python 确定性引擎计算；脱敏队列个体行记录与非白名单单元格值严禁发往外部大模型；合成/模拟输出强制带 non_clinical_evidence 标识。
与后续 Web Wizard 的关系 Web 交互重构已单独建入 GitHub Issue 与需求池；届时前端每一步向导直接调用上述 Stage 1→5 同构状态机，前后端不再重复造两套逻辑。
